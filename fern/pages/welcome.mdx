Lume is a property-management platform for hotels and resorts: a **guest app** that carries a stay from
pre-arrival through checkout, and a **staff dashboard** that runs the property behind it. This reference
documents every route either one calls.

## The shape of a stay

One stay is one Booking ID (`EB-YYYY-NNNNN`), created by [Guest Management](/guest-management) and quoted
by every hub after it — Check-in, Experiences, Spa, Transport, Dining, Requests, Checkout, Notifications.
A typical stay moves through the API in this order:

1. **[Guest Management](/guest-management)** — staff add the guest; this is where the stay is born.
2. **[Guest Arrival](/guest-arrival)** → **[Arrivals Hub](/arrivals-hub)** — the guest completes pre-arrival
   check-in from a tokenized link; staff review IDs and assign a room.
3. **[Guest App Session and Discovery](/guest-app-session-and-discovery)** → **[Guest App Bookings](/guest-app-bookings)**
   — the guest browses the property's catalog (Experiences, Spa, Transport, Dining) and books against it.
4. **[Payments Razorpay](/payments-razorpay)** — a booking is confirmed once it's paid.
5. **[Staff Bookings by Hub](/staff-bookings-by-hub)** — staff manage the same bookings from the dashboard side.
6. **[Checkout and Feedback](/checkout-and-feedback)** — a folio is assembled from everything the stay
   booked, and the guest leaves a review on the way out.

Catalog setup (Experience, Spa, Dining, Food and Beverage, Transport) happens once per property, ahead of
any of this — see those hubs' sections below.

## Authentication

Staff-side routes require `Authorization: Bearer <token>`, issued by
[`POST /api/auth/login`](/staff-authentication) (stateless JWT, no expiry). Guest-facing routes
(`/api/guests/*`, `/api/checkin/*`, `/api/experiences/*`, `/api/bookings/*`, `/api/payments/*`) take no
auth at all — a guest is identified by `guestId`, or by the one-time `bookingToken` in their check-in link.

## Base URL

```
http://localhost:3000
```

Every endpoint below is namespaced under `/api`, except [Health](/health), which isn't.

## Response shape

Every endpoint replies with the same envelope:

```json
{
  "success": true,
  "data": { ... },
  "message": "Operation successful"
}
```

## Where to start

- New to the API? Run [Health](/health) first to confirm the server is reachable, then
  [Staff Authentication](/staff-authentication) to get a token.
- Building the guest app? Start at [Guest App Session and Discovery](/guest-app-session-and-discovery).
- Wiring up the dashboard? [Home Summary and Analytics](/home-summary-and-analytics) gives a property-wide
  overview; each hub below covers its own slice.
